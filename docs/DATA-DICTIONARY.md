# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。

## 夜班餐补

发薪裁决：**不按已确认班次先发，也不无限期等齐**。餐补资格一律由班次有效工作时段（M4 切段结果）判定，切段未完成或重算失败时按下列兜底处理，并阻断封账直到核清。

- 适用：计划班次跨夜（结束时刻不大于开始时刻）的班次；日班不产生餐补记录。
- 夜段：归属日 22:00 至次日 06:00（Asia/Shanghai）。夜段分钟按实际切段与夜段窗口的重叠计算。
- 门槛：夜段分钟 ≥ 300 且有效分钟 ≥ 360 才可发；每班固定 15.00 元，按班不按分钟计。
- 依据：每班记录切段清单（起止、分钟、夜段分钟）、来源行与业务ID、依据摘要 `basis_digest`。页面逐班可核对；原始记录进入封存证据。
- 重跑：同一结算周期（参数 `period`，默认 `2026-10`）内，同班同依据为“重放”，沿用原次数与金额（`revision` 不变，不重复计发）；依据变化则旧版置 `superseded` 失效留痕，新版 `revision+1`。
- 规则变化：补卡/切段/餐补规则版本变化即视为依据变化，旧餐补失效重算，不沿用。
- 重算失败：有同版本旧版可发结果时置 `carried` 沿用金额，强制 `needs_review`，对账不通过、不得封账；规则已变更或无可沿用旧版时置 `blocked` 且金额为 0。
- 对平：餐补合计须等于逐班重算金额之和，并与工资侧 `meal_total`、`payable_total` 一致；任一班金额、合计或工资口径不平，对账 `ready=false`，封账导出返回 422 `UNBALANCED`。
- 旧版失效记录进入 `meal_history`，只留痕不计发；当前可发记录落在 `meal_ledger`。
